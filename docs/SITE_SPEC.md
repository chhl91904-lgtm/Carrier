# CANE MATE 사이트 명세

## 1. 문서 정보

- 프로젝트: CANE MATE 공식 브랜드 웹사이트
- 문서 상태: 구현 전 설계 기준안
- 기준 요구사항: 사용자가 제공한 전체 원문
- 구현 상태: STEP 16 Vercel Production 배포 및 실제 URL 검증 완료 (`https://cane-mate.vercel.app`)
- 관련 문서: `AGENTS.md`, `docs/CHECKLIST.md`

이 문서는 페이지, 사용자 흐름, 기능, 콘텐츠, 데이터 상태, 접근성, 반응형 및 외부 연계 요구사항을 정의한다. 명시되지 않은 제품 성능이나 운영 정보는 추정하지 않는다.

## 2. 제품과 사이트의 포지셔닝

CANE MATE는 폐에어컨에서 회수·재생한 소재와 스마트 기술을 활용하여 시각장애인의 더 안전하고 편리하며 독립적인 이동을 보조하는 스마트 흰지팡이 프로젝트다.

사이트는 오텍캐리어가 실제 제품 프로젝트를 공개한다면 사용할 법한 신뢰감 있는 공식 채널을 지향한다. 다만 검증·상용화 상태가 제공되지 않았으므로 기획 목표, 데모, 외부 협업 관계를 명확히 표시한다.

핵심 사용자군은 다음과 같다.

- CANE MATE 제품 정보와 구매를 원하는 이용자
- 제품을 선물하려는 구매자
- 체험존 방문자와 피드백 참여자
- 보호자 모드와 위치 동의 원칙을 이해하려는 이용자·보호자
- 제품 사용법, A/S, 문의가 필요한 회원·비회원
- 자원순환·접근성 프로젝트의 ESG 가치를 확인하려는 기관·파트너
- 키보드, 화면낭독기, 확대, 모바일 등 다양한 접근 방식을 사용하는 방문자

## 5. 전역 레이아웃

### 5.1 Header와 Navigation

모든 페이지에 동일한 구조를 사용한다.

- 왼쪽: `[Carrier Logo] | [CANE MATE Logo]`
- CANE MATE 로고: HOME 링크
- Carrier 로고: 공식 연결 URL이 제공될 때만 유효 링크, 미제공 시 브랜드 표시
- 오른쪽 비로그인: `LOGIN`, 접근 가능한 장바구니 아이콘, 메뉴 버튼
- 오른쪽 로그인: `MY PAGE`, 접근 가능한 장바구니 아이콘, 메뉴 버튼
- 장바구니에 상품이 있으면 아이콘 옆에 총 수량 badge 표시
- Header 아래 primary navigation 최종 순서: `PRODUCT | EXPERIENCE | ESG | BUY | SUPPORT`
- 현재 페이지는 색상 외에도 밑줄, 굵기, `aria-current="page"` 등으로 구분
- 메뉴 버튼은 모바일에서는 navigation drawer를 열고, 큰 화면에서 노출할 경우 사이트 전체 메뉴를 연다.

스크롤 시 Header 동작 방식은 구현 단계에서 sticky를 기본안으로 사용하되 콘텐츠를 가리키지 않아야 한다.

### 5.2 Floating Shelter Button

- 모든 페이지 오른쪽 하단에 고정
- 문구와 아이콘으로 `외부 쉼터MAP 열기`처럼 목적을 명확히 표시
- 외부 서비스임을 접근 가능한 이름과 필요 시 보조 문구로 알림
- 실제 URL은 중앙 설정값 `SHELTER_MAP_URL` 성격의 단일 값으로 관리
- URL 미확정 시 안전한 placeholder 상태를 사용하며 빈 링크나 `#`로 예기치 않은 이동을 만들지 않음
- 모바일에서 구매 CTA, 쿠키/알림, 브라우저 safe area와 겹치지 않음

### 5.3 Footer

모든 페이지 끝에 동일한 Dark Charcoal/Black Footer를 사용한다.

- 메시지: `더 안전한 이동, 더 나은 일상.`
- 광주인력개발원: 검증된 주소·전화번호·이메일 또는 명시적 placeholder
- 오텍캐리어: 검증된 주소·전화번호·이메일 또는 명시적 placeholder
- CTA: `고객센터 문의 →`, `체험존 찾기 →`
- 하단 문구: `CANE MATE | Carrier ESG Project`
- 연락처와 주소를 임의 생성하지 않음

### 6.2 공통 토큰

구현 시 색상, type scale, spacing, radius, shadow, focus ring, breakpoint, container width를 토큰으로 정의한다. 정확한 색상값은 공식 브랜드 가이드나 승인된 시안이 없으므로 구현 STEP에서 접근성 대비를 충족하는 후보를 제시하고 확정한다.

필수 컴포넌트 상태:

- default, hover, active, focus-visible, disabled
- loading, empty, success, warning, error
- selected/unselected
- available/used/expired
- signed-in/signed-out

### 7.2 PRODUCT

목표는 제품 형태, 핵심 동작, 한계, 내부 구조, 기획 사양 및 앱 연동을 이해시키는 것이다.

#### Product Visual

- 승인된 대형 제품 이미지가 최우선
- 충분한 프레임 자산이 있으면 마우스 드래그·터치·키보드로 조작 가능한 360° view
- 자산이 없거나 성능·접근성 품질을 확보하기 어려우면 자동 회전 영상보다 정적 다각도 이미지 또는 제어 가능한 이미지 sequence를 우선 대체안으로 사용
- 자동 재생 매체가 있으면 정지 제어와 reduced-motion 대응
- 제품 형태는 전체 페이지에서 일관되게 유지

#### 제품 디자인 기준

- 시각장애인용 흰지팡이
- 긴 흰색 shaft
- 검은색 ㄱ자형 Smart Handle
- Wrist Strap
- 4단 접이식
- 검은색 Cane Tip
- 전면의 작은 Dual-Camera Style ToF Sensor
- 조작 버튼
- 내부 Smart Core
- 소형 송풍·온열 구조

#### 기능 설명

1. ToF 보조 감지: 높은 위치의 전방 장애물을 보조적으로 감지. 자연스러운 약 40~45° 사용 상황을 고려한 센서 각도 조절 구조.
2. 햅틱 위험 알림: 장애물 감지 시 손잡이 진동. 길 안내 햅틱과 혼동하지 않도록 주로 위험 알림에 사용.
3. 음성 길 안내: `CANE MATE ↔ Smartphone ↔ Earphone` 연결 구조. 길 안내는 주로 음성.
4. 쉼터 안내: CANE MATE의 쉼 버튼으로 가까운 쉼터 탐색·안내. 위치는 동의 기반.
5. 낙상 위험 감지: IMU 등으로 비정상 충격·기울기를 감지. 즉시 자동 신고가 아니라 보호자 확인 알림. 양측 동의 시에만 위치 확인.
6. 여름 송풍: 손잡이 내부 소형 팬이 가벼운 바람 제공. 냉방장치로 표현 금지.
7. 겨울 온열: 손잡이 온열 필름으로 손의 불편 완화.
8. 휴대·충전: 4단 접이식, USB-C 충전.

각 기능에는 `보조 기능`, `사용 환경에 따라 차이`, `검증 전 기획 내용` 등 필요한 한계 고지를 가까이 배치한다.

  - 낙상 위험 알림

  - CANE MATE 배터리 상태
  - 제품 상태
  - 긴급 상황 확인

보호자 모드도 이용자 동의 없는 상시 추적처럼 표현하지 않는다. 실제 앱 기능이 아니라면 `앱 연동 콘셉트/기획 화면`임을 명시한다.

### 7.3 BUY, CART, CHECKOUT

#### BUY

- 제품 이미지, `CANE MATE`, `149,000원`, 핵심 특징
- `선물하기`, `장바구니`, `구매하기` CTA를 명확히 구분
- 수량 선택은 최소 1, 허용 상한은 운영 정책 확정 전 안전한 데모값으로 설정
- 가격은 정수 원 단위로 계산하고 표시는 한국 원화 형식으로 통일
- 장바구니 담기 성공은 시각·보조기기 모두 알 수 있게 전달

#### 선물하기

- 받는 사람 이름
- 연락처
- 배송지
- 선물 메시지
- 데모 환경에서는 실제 개인정보를 입력하지 말라는 안내
- 일반 구매와 장바구니 항목에서 선물 여부가 유지됨

#### CART

- 상품
- 수량 및 증감
- 가격
- 적용 쿠폰
- 삭제
- 총 금액
- 빈 장바구니 상태와 BUY 복귀 CTA
- Header badge는 장바구니 총 수량과 동기화

#### 쿠폰 정책

- 체험 피드백 완료 시 로그인 회원 쿠폰함에 5% 체험 쿠폰 발급
- 상태: `사용 가능`, `사용 완료`, `기간 만료`
- checkout에서 사용 가능한 쿠폰만 적용
- 한 주문당 적용 수, 중복 발급, 만료일, 최대 할인 금액은 운영 정책 미확정 항목
- 할인 계산은 `상품 소계 → 쿠폰 할인 → 최종 금액` 순서를 화면에 표시
- 이미 사용한 쿠폰 재사용 방지

#### CHECKOUT

순서:

`상품 선택 → 수량 선택 → 쿠폰 적용 → 배송지 입력 → 결제수단 → 최종 결제금액 → 주문하기`

필수 상태:

- 입력 전, 입력 오류, 쿠폰 적용 성공·실패, 주문 처리 중, 데모 주문 생성 성공, 실패
- 결제수단은 실제 PG가 없으면 `데모 결제수단`으로 명시하고 실제 카드번호·계좌정보를 수집하지 않음

- STEP 9 데모에서는 비회원 checkout을 허용하되 회원 쿠폰은 로그인 상태에서만 제공한다. 실제 운영의 비회원 주문 정책과 주문 조회 방식은 별도 승인 항목으로 유지한다.

### 7.4 EXPERIENCE

#### 체험존 소개

복지시설 및 관련 기관에 시제품을 배치하여 직접 제품을 경험하고 사용법을 안내받는 공간으로 설명한다. 단순 홍보 공간으로 묘사하지 않는다.

프로그램:

1. 제품 체험: 실제 CANE MATE를 잡고 사용
2. 스마트 안전 기능 체험: ToF 장애물 감지, 햅틱 알림 등
3. 계절 기능 체험: 송풍·온열
4. 접근성 체험 프로그램: `시각 정보에 의존하지 않아도 안전하게 이동할 수 있는 환경은 어떻게 만들어야 하는가?`를 중심으로 보행환경의 장벽과 접근성을 함께 생각
5. 사용 교육: CANE MATE 사용 방법 안내
6. 사용자 피드백: 실제 의견을 제품 개선에 반영

금지 표현: `시각장애인이 얼마나 불편한지 체험`.

#### 피드백과 5% 쿠폰

흐름:

`체험존 방문 → CANE MATE 체험 → 간단한 피드백 → 5% 체험 쿠폰 발급 → 홈페이지 구매 시 사용`

- 로그인하지 않은 사용자가 피드백/쿠폰 흐름을 시작하면 목적과 데이터 보존 여부를 설명한 뒤 로그인 유도
- 체험 피드백 항목: 무게, 그립감, 햅틱 인식, 버튼 사용성, 기능 만족도, 개선 의견
- 쿠폰 발급 성공 시 상태와 마이페이지 위치 안내
- 중복 발급 규칙은 운영 정책 확정 필요
- 메시지: `당신의 경험이 다음 CANE MATE를 만듭니다.`

#### 일반 후기와 체험 피드백 구분

- 일반 제품 후기: 별점, 후기, 사진, 작성일
- 체험존 개선 의견: 항목별 평가와 개선 의견
- 동일 목록에 섞을 경우에도 유형 label과 설명을 제공
- 후기 사진 업로드는 저장 방식 확정 후 구현하며 데모에서는 안전한 placeholder/file preview만 허용 가능

#### 쉼터MAP 연결

- EXPERIENCE 마지막에 큰 외부 CTA
- 일반 쉼터와 CANE MATE 체험존은 외부 지도에서 구분될 예정임을 설명
- 예시: 지팡이 아이콘, `○○동 CANE MATE 체험존`, `제품 체험 / 사용 교육`
- 실제 장소 데이터는 임의 생성하지 않음
- 외부 서비스가 CANE MATE로 돌아오는 reciprocal link를 둘 수 있도록 안정적인 EXPERIENCE URL을 유지

## 8. 핵심 데이터 모델

정확한 필드명은 구현 시 조정할 수 있으나 다음 관계와 상태는 유지한다.

### User

- id, name, email, phone
- requiredTermsAcceptedAt
- createdAt
- 실제 운영 시 credential은 안전한 인증 제공자 또는 해시 저장; 평문 저장 금지

### Product

- id, name, price, status
- featureSummary, images, planningSpecs, disclaimer
- 단일 CANE MATE로 시작하되 장바구니 구조는 product id를 사용

### Cart / CartItem

- cart owner 또는 guest session
- productId, quantity, giftOption, recipient draft
- appliedCouponId
- subtotal, discount, total은 단일 계산기에서 파생

### Coupon

- id, ownerId, type=`experience-5-percent`
- discountRate=5%
- status=`available | used | expired`
- issuedAt, expiresAt, usedAt, orderId
- 만료일·중복 정책은 미확정

### Order

- id, ownerId 또는 guest reference
- items snapshot, shipping snapshot, coupon snapshot
- subtotal, discount, total
- mode=`demo | live`
- status는 데모와 실제 주문을 혼동하지 않는 명칭 사용
- createdAt

### Review

- id, ownerId, order reference(정책 확정 시)
- rating, body, image metadata, createdAt
- 공개/검수 정책 미확정

### ExperienceFeedback

- id, ownerId, experience reference 또는 self-attestation
- weight, grip, hapticRecognition, buttonUsability, satisfaction, improvement
- couponIssuedId, createdAt

### Inquiry

- id, ownerId nullable
- name, email, phone, type, title, body
- status, createdAt
- A/S는 inquiry type 또는 별도 subtype

### Consent / CaregiverConnection (소개 또는 향후 연동 모델)

- userId, caregiverId
- locationSharingStatus, consentedAt, revokedAt
- connectionStatus
- 웹 데모가 실제 위치를 저장하거나 추적하지 않음

## 9. 주요 비즈니스 규칙

1. 장바구니 badge는 line 수가 아니라 총 상품 수량으로 표시한다.
2. 수량·가격·할인은 음수나 비정상 값이 될 수 없다.
3. 체험 5% 쿠폰은 로그인 사용자의 쿠폰함에 귀속한다.
4. `used` 또는 `expired` 쿠폰은 checkout에서 적용할 수 없다.
5. 쿠폰 적용과 주문 생성은 실제 백엔드 사용 시 원자적으로 검증한다.
6. 데모 checkout은 실결제 정보를 요구하지 않고 데모임을 주문 전후 모두 고지한다.
7. 문의·주문·쿠폰·후기는 소유 회원만 조회한다.
8. 위치 공유는 기본 꺼짐이며 명시적 동의와 철회 가능성이 전제다.
9. 제품 사양·ESG 수치는 기획·검증 상태 label과 함께 표시한다.
10. 외부 쉼터MAP 장애 또는 URL 미설정이 사이트의 다른 기능을 막지 않는다.

## 10. 상태·오류·빈 화면

모든 데이터 기능은 다음 상태를 디자인하고 테스트한다.

- 초기/기본
- 로딩
- 성공
- 입력 오류
- 서버/저장 오류
- 인증 필요
- 권한 없음
- 데이터 없음
- 외부 링크 미설정 또는 외부 서비스 접근 실패 안내
- 네트워크 재시도

오류는 색상만 쓰지 않고 문제, 영향, 사용자가 할 수 있는 다음 행동을 텍스트로 설명한다.

## 11. 접근성 수용 기준

- 키보드만으로 모든 링크, 메뉴, 장바구니, 쿠폰, 폼, dialog, 360° 대체 기능을 사용할 수 있음
- `Skip to main content` 제공
- focus-visible이 배경과 명확히 구분됨
- DOM 순서와 시각 순서가 일치함
- 제목 구조에 건너뜀이나 중복 페이지 H1이 없음
- 일반 텍스트와 UI 구성요소는 WCAG 2.2 AA 대비 기준을 목표로 함
- 200% 확대에서 콘텐츠와 기능 손실이 없음
- 좁은 화면에서 가로 스크롤 없이 핵심 기능 사용 가능(의미상 필요한 표 등은 접근 가능한 예외 처리)
- form label, required, hint, error가 프로그램적으로 연결됨
- 동적 장바구니 badge, 쿠폰 적용, 제출 결과에 적절한 live announcement 제공
- icon-only controls에 이름이 있음
- 제품 이미지·도해·Circular Diagram에 대체 설명이 있음
- drag 조작에는 버튼/키보드 대체 수단이 있음
- 자동 motion은 정지 가능하고 reduced-motion에서 제거 또는 축소
- 외부 링크는 새 창 여부를 예고하며 강제 새 창은 최소화
- 색상, 위치, 감각 정보만으로 지시하지 않음

## 12. 반응형 수용 기준

특정 기기명이 아니라 콘텐츠가 깨지는 지점을 기준으로 breakpoint를 정한다.

- Mobile: 단일 열 우선, 큰 터치 대상, navigation drawer, 구매 CTA와 floating button 충돌 방지
- Tablet: 1~2열 전환, 카드와 form 폭 최적화, 세로·가로 방향 모두 확인
- PC: 제한된 max-width와 충분한 여백, Hero 2열, 제품 visual과 정보 균형
- Header의 브랜드·utility·primary nav가 줄바꿈으로 깨지지 않음
- 긴 한국어 텍스트, 큰 글꼴, 오류 메시지, badge 두 자리 수를 견딤

## 13. 콘텐츠 및 자산 요구사항

구현 전에 가능한 한 다음을 제공받는다.

- Carrier 공식 로고 사용 지침과 파일
- CANE MATE 로고
- 제품 정면·측면·접이 상태·사용 환경 이미지
- 제품 형태를 유지한 Exploded View 또는 제작 가능한 도면
- 360° view를 위한 각도별 frame 또는 승인된 대체 이미지
- 기관별 검증 연락처
- 쉼터MAP URL
- 약관 및 개인정보 관련 실제 문안
- FAQ, 사용 가이드, A/S 정책의 승인 콘텐츠

자산이 없으면 임시 placeholder를 명시하며 AI 생성 이미지가 실제 제품 사진이나 확정 설계처럼 오인되지 않게 한다.

## 14. 분석·측정 원칙

사용자 승인 없이 개인정보성 analytics를 추가하지 않는다. 도입 시에는 다음처럼 목적에 필요한 최소 이벤트만 고려한다.

- 주요 CTA 이동
- 장바구니 담기
- 쿠폰 발급·적용(개인정보 제외)
- 데모 checkout 도달
- 문의 제출 결과
- 외부 쉼터MAP 이동

위치정보, 문의 내용, 선물 수령인 정보, 비밀번호를 분석 이벤트에 포함하지 않는다.

## 15. 보안·개인정보 원칙

- 데모와 운영 모드를 UI와 데이터 계층에서 명확히 구분
- 실제 운영 시 TLS, secure cookie/session, CSRF·XSS·입력 검증, rate limit, 접근 제어 적용
- 비밀번호·결제정보·위치정보를 로그나 analytics에 남기지 않음
- 파일 업로드 시 확장자·MIME·용량·악성 파일 검증 필요
- 위치 동의는 선택, 목적별, 철회 가능하게 설계
- 필수 약관과 선택 동의를 구분하고 동의 이력을 보존
- 법률·규제 준수는 실제 출시 국가와 운영 정책 확정 후 별도 검토
